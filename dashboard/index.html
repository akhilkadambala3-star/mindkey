Wellbeing check-in

How are you feeling today?

A quick answer helps MindKey understand whether anything everyday — like a late night or a stressful day — could explain a recent variation. There are no wrong answers.

Why check in?

Typing can vary for many reasons. When a variation lines up with something you've told us about — stress, poor sleep, feeling unwell — MindKey treats it as contextualized: it stays in your history, but it's understood differently.

A variation is only flagged as persistent when it remains unexplained across several sessions.

    What MindKey collects

    • Typing timing and rhythm — dwell time, flight time, speed, pauses, corrections
    • When sessions happen and how long they last
    • Aggregated behavioral metrics built from those sessions
    • Check-in responses, if you choose to give them
    • Symptom responses, only if you complete the optional questionnaire

    What MindKey never needs

    • The content of what you type — messages, documents, or code
    • Passwords or anything entered into a password field
    • Private conversation text in any app
    • The words themselves — only the timing between key presses matters
    • Documents, files or screenshots

    Where processing happens

    Your device

    Keyboard timing events are read by the desktop agent.

    Feature extraction

    Dwell, flight, speed, pauses, corrections — computed locally. Keys are discarded.

    Aggregated metrics

    One row of numbers per 20-second session. No text, no key identities.

    MindKey server

    Baseline, anomaly model and investigation run on those numbers only.

    Privacy boundary: nothing you type leaves the first two steps.

    The desktop agent extracts typing features locally on your device and only timing-derived aggregates are sent to the server. The words you type never leave your computer. Planned: run more of the analysis — including anomaly detection — entirely on-device.

    Demo data

    MindKey is currently running on demo data, so the whole product can be explored without a connected backend. The sessions and check-ins are synthetic, not real typing. The ML scores and the investigation are real: the backend's Isolation Forest and agent were run on this data.

    The Monitoring card also simulates the desktop agent: a simulated session lasts 20 seconds and stops at the same daily limit as the real agent in agent/listener.py.

    Data source

    • Simulated demo data (active)
      Synthetic sessions and check-ins for seven scenarios, with real ML scores and real agent output computed from them (see the Demo Lab). The Monitoring card's agent status is simulated.
    • MindKey backend API (not connected)
      The backend serves sessions, baseline, check-ins and the full investigation (trace, evidence, hypotheses). The dashboard starts in demo mode; to read live data, run the backend and open the dashboard with ?api=http://localhost:8000&user=<your-user-id>. No Supabase?
